# 文稿审核台 · Review Desk

> A three-column manuscript review workspace for [DeepSeek Harness](https://github.com/deepseek-ai)（DSH）：
> 左边读稿，中间做审核，右边留下全部过程。

选中一段文字，就能做 **来源查证 / 逻辑分析 / 扩写 / 关联分析**，或者直接写一句要求（"压缩到 60 字""换成汇报口径"）让它照办；改写结果自动替换原文并可撤销，每一版都留在结果栏里。支持导入 `.docx` / `.pdf`，并按原文档结构转成 Markdown 阅读与编辑。

本插件面向 **DSH Web / Desktop**，安装后出现在左侧栏，是一个全局面板（与「插件」「设置」同级）。无构建步骤，`client.js` / `index.js` 就是源码。

---

## 功能

| 能力 | 说明 |
| --- | --- |
| **来源查证** | 先让模型出检索式 → 调用 profile 里已配置的联网检索 → 把带编号的资料交给模型逐条判断「有据可查 / 部分一致 / 相互矛盾 / 无法核实」，结论标注 `[S1]`，下方列出参考资料 |
| **逻辑分析** | 论证结构、逻辑问题（按严重度、摘录原文、给修改方向）、收紧建议 |
| **扩写** | 输出可直接入稿的成品，单独成块，一键替换原文 |
| **关联分析** | 结合全文，给呼应 / 冲突 / 缺口与统稿建议 |
| **自定义要求** | 自由文本指令；判定为改写时自动替换选中文字（可撤销），问答类要求不动原文 |
| **结果工作流** | 最新一条展开、其余折叠成摘要；按类型分页签筛选；每张卡片可「修改」追加要求，形成修订链 |
| **原文标记** | 审阅过的段落带底纹，结果可一键定位；**点击划线会跳到对应结果并高亮——同一段做过多次操作时全部一起高亮**；原文改动后失效标记自动丢弃 |
| **导入排版** | `.docx` → 保留标题级别、列表、加粗/斜体、表格；`.pdf` → 按基线重建段落。导入后自动进入渲染预览 |
| **原件** | 用本机排版引擎把原 `.docx` / `.doc` / `.pdf` 逐页渲染成图片，用于核对版式（只读，前 8 页） |
| **模型** | 选择 profile 里已注册的任意模型通道，单独设置推理等级 |
| **审核包** | 一个 JSON 文件带走文稿、全部结果与当前要求，换台电脑继续 |
| **三栏宽度** | 两条分隔条可拖拽 / 键盘调整，宽度本机记忆 |

细节：深浅色跟随宿主主题、常显滚动条、`⌘1–⌘4` 触发四项分析、`⌘↩` 执行要求、`Esc` 关闭浮层、可聚焦的分隔条（`role="separator"`）、`prefers-reduced-motion` 与触摸命中区适配。

## 安装

### 1. 本地目录（推荐）

```sh
git clone https://github.com/lzyxczw-cyber/dsh-review-desk.git
```

然后任选其一：

- **界面**：DSH → 侧栏「插件」→ 添加插件 → 选择本地目录 → 指向 clone 下来的目录；
- **Agent 工具**：让 DSH 里的 agent 调用 `plugin_manager` 的 `install_bundle`，`target` 填该目录的绝对路径。

安装后重启或刷新页面，左侧栏出现「文稿审核台」。

### 2. 依赖

- DSH 已配置至少一个模型通道（审核请求走 profile 的默认模型或面板里选的模型）；
- 「来源查证」需要 profile 里配置了 web search provider（没有时会明确提示，其余功能不受影响）；
- 「原件」需要本机 office 渲染引擎（`officeKit`）。没有时会显示原因，不影响其他功能；
- 本插件不额外声明 npm 依赖，也没有构建步骤。

## 使用

1. 打开「文稿审核台」，在左栏粘贴文字，或「导入 → 导入文稿」选择 `.docx` / `.pdf` / `.md` / `.txt`；
2. 在中栏拖动选中一段文字（预览模式下也能选），点四项分析之一，或写下要求后点「执行要求」；
3. 结果出现在右栏：最新一条自动展开，可复制、替换原文、撤销替换、追加修改、定位回原文；点左栏的划线也能反向跳到并高亮对应结果；
4. 「导出 → 导出审核包」生成 `.review-desk.json`，换电脑「导入 → 导入审核包」继续。

## 数据与隐私

- 文稿、结果、列宽、模型偏好都只存在**本机浏览器**（`localStorage`，键前缀 `dsh.review-desk.`）；
- 每次分析会向所选模型发起一次请求；来源查证会先调用已配置的联网检索；
- 插件**不保存任何 API Key**：第三方 OpenAI 兼容接口请在 DSH「设置 → 模型」中添加，密钥由 DSH 凭据服务保管；
- 浏览器请求走 DSH 的 `/api` 鉴权通道，路由只对 owner peer 开放；
- 审核包是明文 JSON，分享前请自行确认内容。

## 限制

- PDF 只读取**文字层**；扫描件会提示另存为 `.docx`。旧版 `.doc` 不支持（`.docx` 可以）；
- 「原件」最多渲染前 8 页、文件 ≤30 MB；它只是版式参照，**不是所见即所得编辑器**——正文编辑在「编辑」栏以 Markdown 进行；
- 替换原文依赖模型输出的 `<<<TEXT … >>>` 标记或要求措辞判断；不确定时打开「改写后替换原文」开关即可强制替换（仍可撤销）；
- 审核包不含原始 `.docx` / `.pdf`，也不含列宽、模型等本机偏好。

## 开发

```sh
cd tests
npm install
npm test          # host-test.mjs + client-test.mjs
```

- `index.js`：Host 半。注册两条鉴权路由（`/api/review-desk/analyze`、`/api/review-desk/original-pages`）与 agent 工具 `review_manuscript`；负责提示词、流式 NDJSON 帧、检索取料、原稿渲染。
- `client.js`：浏览器半。无框架、无构建，`React.createElement` + 手写 CSS；注册 `main` 面板与 `sidebar.panellist` 入口；Markdown 渲染、docx/PDF 解析、审核包都在这里。
- `tests/host-test.mjs`：用假 Cordis 上下文驱动路由与工具，断言帧协议、提示词、检索、失败路径；16 项。
- `tests/client-test.mjs`：在 jsdom 里挂载真实面板，驱动选择、运行、折叠、页签、导入、列宽、审核包；33 项。

目录：

```
.

├── package.json          # bundle / client 声明
├── locale/{zh,en}.json   # 插件市场里的标题与说明
├── docs/                 # 详情页文档与示意图
├── icon.svg
└── tests/                # 可在 Node 里跑的检查
```
