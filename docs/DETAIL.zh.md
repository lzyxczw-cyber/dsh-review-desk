## 它解决什么

一份稿子要过来源、逻辑、表述、统稿几道关，每道关的痕迹通常散在批注、聊天和另一个文档里。文稿审核台把"读稿—提要求—留结论—改回原文"放在同一个三栏界面里：左边是稿子，中间是审法，右边是这一稿的全部过程。

## 怎么用

1. 导入或粘贴文稿（`.docx` 保留标题、列表、加粗与表格；`.pdf` 按段落重建）。
2. 在文稿里选中一段，点四项分析之一；或者在要求框里直接写"压缩到 60 字""换成汇报口径"。
3. 结果落到右栏：最新一条展开，其余折叠；改写类结果自动替换原文，可撤销；不满意就在卡片上继续追加要求。
4. 点左栏的划线可以反向跳到并高亮对应结果；一段做过多次操作时，全部一起高亮。

## 编辑视图

「编辑」按块渲染：表格、图片、标题、列表都是所见即所得的样子，点任意一段就在原地编辑该段的 Markdown，其余内容不动（`Esc` 放弃、`⌘↩` 完成）。需要大段改写或粘贴时切到「源码」，就是传统整篇文本编辑器；「预览」为只读。

## 数据

文稿、结果、列宽与模型偏好只存在本机浏览器。顶部「导出 → 导出审核包」把文稿、全部结果与当前要求打成 JSON，换一台电脑「导入 → 导入审核包」即可继续，不含原始 docx/pdf 文件。
